# Functional Requirements (MCP Server)

## FR-QB-001 Built-in, non-disableable plugin

### FR-QB-001 (New): Built-in, non-disableable plugin
TR-QB-PLUGIN-001 (New): Construct the pinned plugin through a protected integration adapter outside optional discovery/filtering. Bundle required assets, avoid duplicate SDK runtimes/dependency cycles, and reserve required contribution identities.
- AC-QB-001: Startup automatically registers required tools, skills, and lifecycle capabilities without install/enablement prompts. TEST-QB-001: registers_bundled_plugin_without_user_enablement. TDD: P1.
- AC-QB-002: Settings, flags, environment variables, tool filters, and same-name optional contributions cannot disable/replace required capabilities. The named test covers every enumerated bypass surface, optional hook input rewrites and provider-executed tools: only final authorized arguments execute; an adapter with unobservable execution is rejected unless tool execution is verifiably disabled. TEST-QB-002: rejects_required_plugin_disable_and_shadow_attempts. TDD: P1.
- AC-QB-003: Missing, incompatible, incomplete, or invalid plugin assets block ordinary execution before the first model request. Pin, signed ClineQb entry, asset digest and host-platform compatibility must agree. Missing runtime prerequisites for a non-triggered skill do not block unrelated work; triggering that skill without its prerequisite blocks that workflow with an actionable diagnostic. TEST-QB-003: blocks_execution_when_required_plugin_is_unusable. TDD: P1.
- AC-QB-068: Compiled desktop normal and configured-proxy startup use the selected cline-qb state and hub namespace, ignoring inherited upstream CLINE_* overrides. Executable validation uses a distinct temporary home, private state/discovery paths and OS-assigned ports, inherits no operator provider/account credentials, and cannot read or modify the operator home or attach to an operator hub. Seeded upstream canaries remain byte-identical with no new files after either readiness or a blocked startup. Missing trusted runtime identity blocks before publishing readiness; it is not accepted as a successful startup. Both positive readiness cases remain required once reviewed signed runtime dependencies are available. TEST-QB-068: isolates_compiled_startup_and_ignores_upstream_overrides. TDD: P1.
- AC-QB-070: For the approved PowerShell shared-core contract, an ordinary governed launch on a clean supported host works using the pinned, verified runtime and every mandatory startup module/asset supplied by the artifact, without a user module cache, startup installation or runtime download. Runtime, module, host-interface and platform compatibility are checked together before readiness. Missing, incompatible or shadowed prerequisites give an actionable blocked state without an ungoverned fallback. Preserve the agreed C1-C12 observable behavior through migration. P1 proves the integration on its available execution host; P5 verifies every declared package target using the existing executed-versus-static-only matrix and its honest limitations. TEST cases: Empty module cache and no network; incompatible pwsh/module/REPL versions; wrong architecture; PATH or module shadow; omitted YAML or PowerShell.MCP dependency; supported diagnostic recovery; clean packaged launch; all required target builds present. TEST-QB-070: verifies_complete_pinned_powershell_runtime_offline. TDD: P1. Staged regressions: P5.

## FR-QB-002 Trusted, workspace-bound startup

### FR-QB-002 (New): Trusted, workspace-bound startup
TR-QB-TRUST-001 (New): Resolve trust/routing from actual workspace; isolate contexts instead of process-global session state; maintain guidance in provider requests.
- AC-QB-004: Signature/nonce/health/auth failures block ordinary execution without unauthorized further probing or ungoverned fallback. TEST-QB-004: fails_closed_on_workspace_trust_failure. TDD: P1.
- AC-QB-005: Concurrent workspaces/sessions retain separate endpoints, credentials, session linkage, and request IDs. Steering, delayed callbacks, replay, resume and clear/end preserve the captured workspace, agent, MCP session, request and event attribution. With multiple delivered open turns an implicit write is request_ambiguous; a foreign request is request_unknown. A mint-only request is not an implicit write target; explicit valid targeting still works without canceling another open turn. TEST-QB-005: isolates_concurrent_workspace_and_session_contexts. TDD: P1.
- AC-QB-006: Required skills/guidance precede work and survive requests/compaction; unavailable guidance is not false successful emptiness. Assert the complete pinned skill inventory, memory descriptor output and effective requirements in actual provider requests after prompt replacement, rebuild and compaction; successful empty memory alone permits None. Marker/bootstrap prompt text is absent, and unrelated skills do not execute automatically. TEST-QB-006: preserves_required_guidance_and_rejects_false_empty_results. TDD: P1.
- AC-QB-072: At each ordinary execution and completion authorization boundary, a live context whose relevant signed trust, credentials, artifact authorization or policy has changed cannot authorize new work using its previous validation. It must revalidate the applicable current state or block with supported recovery. In-flight effects and late callbacks retain their original attribution and cannot mark a replacement context ready. Recovery retains the original audit records and cannot silently rebind them to another identity. An unaffected concurrent context continues normally. Supported changes, detection boundaries and in-flight outcome rules must be specified by the slice contract before implementation. TEST cases: Marker/key/policy change between initialization and tool execution; change between verification and completion; change while a tool is already executing; delayed response from old context; failed revalidation; unrelated concurrent workspace; restart with an old outbox. TEST-QB-072: invalidates_live_authorization_after_trust_or_policy_change. TDD: P1.

## FR-QB-003 Durable session auditing

### FR-QB-003 (New): Durable session auditing
TR-QB-AUDIT-001 (New): Use supported plugin lifecycle/action/decision/persistence/recovery interfaces; keep decisions distinct from actions.
- AC-QB-007: Every actual user request opens a linked turn with the full request text before agent work, using a deterministic provisional title derived from the request that is never empty and never the literal User prompt; before completion the turn carries a summary title meeting completion obligation (d). TEST-QB-007: opens_linked_request_turn_before_agent_work. TDD: P1.
- AC-QB-008: Outcomes/errors/cancellation/decisions retain status, ordering, and separate action/decision classification. tool_execution is emitted only after the server/REPL/plugin taxonomy prerequisite is verified. One explicit decision has the same identity and conclusion in designDecisions, decision dialog and design_decision action after replay; tool activity alone does not invent a decision. Out-of-order acknowledgments cannot reorder stored events or transfer a canceled/terminal turn outcome to another request. TEST-QB-008: records_ordered_actions_and_separate_decisions. TDD: P1.
- AC-QB-009: Pending/synthetic acknowledgments are not confirmed persistence; recovery retains records and avoids duplicate application. Crash/restart at capture, pending-to-minted rebinding, submission, server commit, receipt handling and retirement retains immutable event identity, payload and per-turn order. At-least-once replay applies one logical event and never changes its request attribution. Confirmed and verified-unchanged receipts require matching root identities, event/payload and positive committed revision; duplicate requestIds and identical resubmission follow the agreed C3 outcomes. Alias recovery survives clear/restart and is not forgotten before durable consumer acknowledgment. Queued, rejected, lost, quarantined or retry-capped mandatory evidence remains visible and blocks successful completion; an empty queue cannot erase a retained rejection. TEST-QB-009: distinguishes_confirmed_audit_from_pending_recovery. TDD: P1.
- AC-QB-069: For every actual user request, including steering, the confirmed record preserves its complete request and final response text prepared for delivery, under the captured workspace, native session, MCP session and request identities, subject only to the existing secret policy and this operator-approved storage normalization: U+2013 and U+2014 become U+002D. Those two Unicode dash characters must not be stored; do not bypass the REPL normalization with escaping. After that policy, server readback is ordinally identical to the full expected text, preserving all other Unicode, Markdown, whitespace and newlines without trimming or summarization. A title or summary may be separate metadata but never substitutes for the response. Completion checks the expected request/event/result set, not only empty queues or equal counts. Missing, summarized, truncated, duplicated, misattributed or otherwise modified content blocks successful completion and remains visible for recovery. Cancellation without a final result does not invent one. Replay preserves one logical record and the same normalized full text. A crash after persistence but before delivery must not be represented as proof that the operator received the response. TEST cases: Both prohibited dash characters normalize to ASCII hyphens; literal and escaped input cannot retain prohibited dashes; existing ASCII hyphens and unrelated Unicode remain unchanged; exact whitespace/newline/Markdown response; same-count wrong request; summary substituted for result; omitted ingress event with zero pending counters; steering before/after response persistence; two sessions with identical text; timeout before/after server commit; crash before actual delivery; redaction identical on both output boundaries. TEST-QB-069: preserves_exact_request_and_final_result_with_complete_turn_coverage. TDD: P1.

## FR-QB-004 Enforced completion obligations

### FR-QB-004 (New): Enforced completion obligations
TR-QB-COMPLETION-001 (New): Await a pre-completion gate for completion tools, text-only replies, success events, and final delivery; verification matches current changed state.
- AC-QB-010: Successful final-answer payloads/success events remain withheld until required checks pass; blocked or incomplete diagnostics remain deliverable without claiming success. Test successful, correctable-incomplete and infrastructure-blocked outcomes through each final-delivery path. A corrected final attempt uses the same open request and only succeeds after every applicable obligation is verified; unchanged incomplete attempts stop at the existing bounded limit. Infrastructure failure exposes supported recovery without allowing ordinary work or discarding audit evidence. TEST-QB-010: gates_all_successful_completion_paths. TDD: P1.
- AC-QB-011: Code/doc edits and command-made changes invalidate stale evidence; failed/missing applicable checks block completion. The signed policy selects every applicable runner from package ownership and dependency scope, including non-sdk VS Code suites, all distinct desktop runners and required native checks. Evidence binds policy digest and pre/post source fingerprints; changes during verification invalidate it. Ignored receipt churn alone does not invalidate source evidence. Baseline failures, blocked chains and required platform/credential cases remain explicit blockers until resolved or changed by an operator decision. TEST-QB-011: blocks_completion_on_failed_missing_or_stale_verification. TDD: P1.
- AC-QB-012: A host-owned classifier derives phaseId and phaseClosing from trusted governed TODO/task mutations and MCP records, never model prose. It classifies operationClass from that trusted state plus source fingerprints: any working-tree content change within the verification-policy scope is development, whether made by an edit tool or command; administrative turns have unchanged source contents and only TODO, requirement or session-record effects. Administrative turns carry no verification or HV obligation; development turns complete only after required verification passes for the current fingerprint; a mutation completing a task or setting done: true on a TODO listed as phase-gated by the signed workspace verification policy is rejected without a valid HV receipt; for this workspace the policy lists QB-AGENT-001 tasks prefixed P1: through P5: and Final:, and done: true on QB-AGENT-001; TODOs without a phase-gate entry carry no HV obligation. The named test rejects forged reviewer/root identities, model-selected phase selectors, partial or missing verdict persistence, absent scores and every sub-98 value without rounding; it accepts valid lexical scores only under the agreed lossless numeric contract. Canonical task readback must match the attempted phase transition and current verified plan/base/head; read failure or mismatch leaves that transition pending. Administrative reconciliation never satisfies a product AC or silently closes a phase. TEST-QB-012: classifies_operations_and_gates_phase_closure_on_verified_hv_receipt (administrative, development, valid receipt, forged receipt, stale receipt). TDD: P1. The host binds model-facing session tools to its own agentIdentity and sessionId; tool arguments cannot set agent, sourceType or sessionId. An administrator or unrestricted user-authorized shell with the raw marker key can bypass the application and forge server records; this on-disk credential bypass is outside the application-level guarantee and is documented as a limit under AC-QB-054.
- AC-QB-071: Every required verification fixture and its child processes use isolated application state and explicitly selected test identities, workspace, discovery endpoints and ports before application initialization. Tests must not read live operator credentials, attach to a live operator hub or change operator application state. Seeded external-state canaries and inventories remain unchanged after success, assertion failure, timeout and cancellation. Cleanup affects only resources owned by that test run. Any intentionally live integration fixture uses an explicitly provisioned test account/workspace and cannot silently inherit the operator account. Read-only compiler/package caches may be shared when they contain no operator application identity or mutable product state. TEST cases: Pre-import environment capture; account feature-flag callback; real HOME inherited by a child; parallel fixtures; wrong discovery file/port; failure and timeout cleanup; mocked negative fixture plus a real compiled positive launch; canaries outside the test root. TEST-QB-071: isolates_all_verification_processes_from_operator_application_state. TDD: P1. Staged regressions: P2, P3, P4, P5.
