# QBrain host governance

Private host policy for the QBrain Cline application. Generic SDK packages do not import this package.

`createCompletionGate(scope, readEvidence)` supplies `AgentRuntimeConfig.completionGate`. Create one instance for each governed host turn and pass the same turn-bound gate through the Core runtime configuration. The evidence reader belongs to the trusted host, not model tools, user settings or optional plugins.

The host must authenticate the workspace/session/turn context and signed policy, drain mandatory audit writes, derive the current source fingerprint, and validate verification/decision/title/HV records before returning evidence. `trust: verified`, `decision: attested-none` and `phaseReview: verified` are results of those host checks; this package does not verify signatures or accept raw model assertions. Production evidence collection and product composition are not yet wired.

Completion requires all mandatory audit writes persisted. Pending, rejected, quarantined or lost evidence blocks completion immediately, as do invalid trust, unavailable infrastructure and missing verification configuration. Code changes require exactly one passing record per required check for the current fingerprint and policy. Development also requires a recorded decision or explicit no-decision attestation. Every turn requires a summary title; phase-closing operations additionally require verified HV agreement.

Correctable obligations return diagnostics and permit another model attempt. The signed policy may choose a limit from one to three attempts with unchanged fingerprint and obligations; reaching that limit returns blocked. Completing tools must be submitted alone, so concurrent ordinary tools cannot invalidate the evidence after success. Changed obligations or source fingerprint restart the correction count. Durable audit recovery remains owned by the plugin journal/outbox; this gate never deletes evidence or treats an empty pending queue as proof when rejected records remain.

Run `bun run build:sdk` from `sdk/` before package tests. From this directory, `bun run test` runs Vitest against `src/**/*.test.ts`; `bun run typecheck` checks source and tests. The repository SDK build and workspace typecheck globs include this package. Register its runner in the signed workspace verification map before any product completion relies on that policy.

## Pinned plugin installation

`preparePluginInstallation({ bytes, binding, requiredFiles })` consumes a copy of the bytes returned by canonical plugin-core's `verifyPinnedPluginArtifact().readBytes()`. Supply the same host-reviewed package name, version and archive SHA256 that required signed-marker bootstrap checks. This API rehashes the captured bytes; it does not authenticate a marker or grant approval to a caller-selected pin. `requiredFiles` is the reviewed host asset list, supplemented automatically with `package.json` and `dist/index.js`. The manifest must match that identity/version and declare the expected ESM main/export.

Parsing uses the already-locked `tar` 7.5.22 library. Accepted input is a tar or gzip tar with a single `package/` root. Limits are 64 MiB archive, 256 MiB total decompressed bytes (including metadata/padding), 32 MiB per file, 4,096 entries, 64 KiB per metadata entry and 240 ASCII characters per archive path. Traversal, absolute/drive paths, backslashes, Windows device names, case aliases, duplicate entries, file/directory conflicts, symlinks, hardlinks and special files fail before filesystem writes. No package installation scripts or plugin code run during this operation.

The returned immutable preparation owns the exact expected file bytes and hashes. `install(parentDirectory)` requires an existing absolute host-owned private product directory with no symlink ancestors; the host must resolve it through QBrain storage policy. Each install gets a fresh private directory and returns its root and entrypoint only after verifying the entire tree. A failed write removes only its own directory where possible. Crashes may leave inert incomplete directories; these are never selected or reused. Parallel installs have different directories. Product lifecycle cleanup of retired installations remains a host responsibility.

`verify(rootDirectory)` checks every expected file's bytes and detects missing files, unexpected entries, links and changed assets, including non-code assets. Reconstruct the preparation from pinned archive bytes after restart, and verify immediately before loading. A mutable receipt on disk never supplies the expected inventory. Privileged or same-account replacement after verification is outside this filesystem check's guarantees; hosts must not expose the installation directory to model writes. Native Windows/macOS behavior, final V2 bundle/dependency closure and mandatory product factory integration remain acceptance work. This primitive alone does not certify a running governed host.
