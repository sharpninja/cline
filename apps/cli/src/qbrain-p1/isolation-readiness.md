# Synthetic external-state isolation contract (P1 test readiness)

This increment adds real task-owned filesystem observations to the frozen host contract. It does not run an application host, governed runtime, network provider, daemon, child cancellation or alias/symlink path. The 29 host/entry names remain model input labels.

`assertIsolatedHost` accepts one provider factory for Mock and later authorized Production. It invokes the unchanged `assertScenario` for the captured request, provider, audit, delivery and open-turn assertions. Independently, it inventories real synthetic original/peer files before and after the operation, compares byte payloads and filenames, checks the derivative journal's exact captured binding and full request/result, and compares ordered environment/root/hub/credential/storage accesses. The provider receives only operation inputs, scripted dependency responses and the captured I/O boundary. It receives no scenario or expected object.

Fixtures contain a derivative root plus separate original and peer roots under a unique task-owned run directory. External means outside the derivative application root, not outside the task-owned fixture. All credentials, endpoints and identities are synthetic. No real home, Cline discovery, provider secret or daemon is consulted. The focused PowerShell runner clears inherited environment before starting Bun and selects synthetic HOME, USERPROFILE, temp and application cache roots. Fixtures and streams are retained.

The correct cases cover 29 existing host/entry labels and three scripted failure/timeout/cancellation responses. Twenty controls per successful case change actual files, reads, writes or dependency-returned values, including changed/deleted canaries, extra files, crossed roots/namespaces/identities, forbidden credential/hub/env access, omitted storage, early hub access and incorrect stored results. A false unchanged acknowledgment follows an actual byte mutation. An unlogged write is still rejected by the independent inventory. Only assertion failures qualify as rejected controls; incidental exceptions fail the gate.
